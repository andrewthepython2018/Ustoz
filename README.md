# Ustoz

Веб-платформа репетиторов и курсов учебных центров Узбекистана. Русский и узбекский интерфейс, цены в UZS, расписание в Asia/Tashkent. Рабочая первая версия с серверной базой и файлами.

## Что работает

- Каталоги репетиторов и курсов: поиск, предмет, язык обучения, город, формат, диапазон цены, опыт и уровень; сортировка по цене, рейтингу и новизне. Ссылки сохраняют фильтры.
- Регистрация и вход по email, кабинеты ученика, преподавателя и центра; отдельная роль администратора.
- Несколько управляемых кабинетов под одним входом: отдельные предложения, расписание, задания и переписка каждого преподавателя или центра.
- Ручное редактирование имён и направлений, загрузка фотографий и обложек JPG/PNG/WebP до 5 МБ, сохранение черновиков и публикация в каталоге.
- Создание и редактирование предложений, свободные слоты, индивидуальная запись и группы до 30 мест, отмена, защита от пересечений и переполнения.
- Календарь и список занятий, HTTPS-ссылки на видеоуроки.
- Выдача задания, ответ и файл до 10 МБ, оценка и обратная связь.
- Личная переписка, избранное, профиль, уведомления внутри кабинета, отзывы после завершённого занятия.
- Серверная проверка доступа, приватные файлы и автоматические интеграционные проверки.

Каталог и новые кабинеты изначально пустые. Преподаватели и центры создают свои предложения вручную; автоматических курсов и анкет нет. Обновление включает миграцию `0003_remove_starter_offers`: она удаляет неизменённые черновики прежней подготовки АФ МИСИС и пустые автоматически созданные кабинеты. Отредактированные предложения, настоящие аккаунты и учебная история сохраняются. Миграция применяется автоматически при `npm run deploy`. Это MVP: оплата, email/SMS, восстановление пароля и другие последующие модули описаны в [архитектуре](docs/ARCHITECTURE.md).

## Локальный запуск

Нужны Node.js 22.13+ и npm. Windows, macOS и Linux поддерживаются.

```sh
git clone https://github.com/andrewthepython2018/Ustoz.git
cd Ustoz
npm ci
npm run build
npm run db:local
npm run dev
```

Откройте URL из терминала (обычно http://127.0.0.1:5173). Сначала создайте аккаунт преподавателя, опубликуйте предложение и свободный слот. В другом браузерном профиле зарегистрируйте ученика и запишитесь на этот слот. Преподаватель увидит ученика, сможет выдать задание и проверить ответ. Для курса регистрируйтесь как учебный центр.

Локальные данные находятся в `.wrangler/state`, не отправляются на GitHub и не попадают на хостинг. Новая версия миграций: `npm run db:generate`, затем `npm run db:local`. Миграции применяются только один раз.

## Деплой в собственный Cloudflare

Однократно создайте необходимые ресурсы в своём аккаунте:

```sh
npx wrangler login
npx wrangler d1 create ustoz-db
npx wrangler r2 bucket create ustoz-files
```

Скопируйте `deployment.config.json.example` в `deployment.config.json`, впишите выданный `database_id` и фактическое имя R2-бакета. Этот локальный файл исключён из Git. Затем:

```sh
npm run deploy
```

Скрипт собирает проект, подключает ваши D1/R2, применяет миграции и публикует Worker. URL выводится Wrangler. Для последующих обновлений достаточно `git pull`, `npm ci`, `npm run deploy`. Домен подключается в настройках Worker. Ресурсы и тариф выбираются в вашем аккаунте Cloudflare; скрипт не подключает платёжные системы.

Поддерживаются также переменные `D1_DATABASE_ID`, `D1_DATABASE_NAME`, `R2_BUCKET_NAME`, `WORKER_NAME`; для автоматического деплоя используются стандартные `CLOUDFLARE_ACCOUNT_ID` и `CLOUDFLARE_API_TOKEN`. Токены храните в секретах CI, не в исходниках. Подготовленный GitHub Actions запускает проверки; автоматическая публикация без ваших настроек не включена.

[Официальные команды D1](https://developers.cloudflare.com/d1/wrangler-commands/), [создание R2-бакета](https://developers.cloudflare.com/r2/buckets/create-buckets/).

## Публикация через Sites

`.openai/hosting.json` содержит идентификатор закрытого превью и логические привязки DB/BUCKET. Sites синхронизирует исходники и разворачивает Worker со своей базой и хранилищем. Предпросмотр по умолчанию закрыт владельцу. GitHub-репозиторий остаётся независимым; собственный Cloudflare-деплой не требует Sites.

Дополнительный вход через ChatGPT работает только за доверенным Sites-прокси и с переменной `TRUST_SITES_IDENTITY=true`. Скрипт собственного деплоя принудительно оставляет её `false`; email-регистрация продолжает работать. Секретов в `.openai/hosting.json` нет.

## Проверки

```sh
npm run check
npm run test:migrations
npm run build
npm run db:local
npm run test:integration
```

Миграции отдельно проверяются 11 сценариями в памяти: очистка старых заготовок и сохранение реальных данных. Интеграционным тестам нужен работающий локальный сервер. Они создают отдельные тестовые аккаунты и проверяют 55 сценариев, включая изоляцию кабинетов, публикацию черновиков и доступ к фотографиям. Тестовый скрипт запрещает запуск по внешнему адресу и никогда не заполняет production-базу. Для проверки собранной версии без отдельного сервера: `node scripts/test-ci.mjs`.

## Структура

- `app/` — страницы и HTTP API.
- `components/` — каталог, кабинеты и формы.
- `lib/` — данные каталога, перевод интерфейса, клиентский контекст, серверные функции.
- `db/`, `drizzle/` — схема и последовательные SQL-миграции.
- `scripts/` — сборка, миграции, проверка и деплой.
- `tests/` — сквозные проверки API с разными ролями.
